# sabai 2.1.0 — design

Date: 2026-10-11 · Mod: `sabai` · Status: approved in conversation, awaiting spec review

## Goal

Make sabai steadier and a little smarter. The guard must never fail open. Each turn that did work ends with a one-line receipt. The guard gains a rule and a per-rule choice of refusing or asking. Clawd shows how the session is going. Desktop Code tab first; the terminal gets the same information as text.

## What the API says (types, not yet seen on the desktop)

| Finding | Use |
|---|---|
| `turn.complete`: returning `{ text }` with a different text shows it beneath the answer; the transcript's record is never rewritten, and a hook that fails leaves the answer as it was. | The receipt (A1). |
| `classic.PreToolUse` answers `{ allow }`, `{ ask: reason }` or `{ deny: reason }`; `ask` asks the user before the call runs, with the text as the reason. | The guard's Ask (A2). |
| At every engine event, a hook that fails is skipped and the hooks beneath and core run in its place, so a guard fails open unless its registration carries a `.catch` that refuses. | 0a. The other gating hooks (`TaskCreate`, `TodoWrite`, …) fail open correctly: they only observe, so they keep no `.catch`. |

## Task 1: desktop spike (before anything is built on it)

A throwaway probe, removed afterwards. The owner checks the screen:

1. A main turn's `turn.complete` returns `{ text: '✎ receipt probe' }`. Is the text drawn under the answer, and how is it drawn: plain text, Markdown, or nothing?
2. A `classic.PreToolUse` hook answers `{ ask: 'probe' }` for one harmless Bash command. Does a permission dialog open with the reason, in auto mode and in default mode?
3. Left over from 1.1.0:
   - a run of Reads unfolds into its own steps (`ToolGroup`);
   - the Thai spinner word shows in place of `Working`.

Fallbacks:
- If (1) draws nothing, the receipt becomes a toast (`$.ui.toast`) on turn end.
- If (2) shows no dialog in a mode, that mode treats Ask as Block, and the Settings note says so.

The findings go into CLAUDE.md's engine constraints.

## 0a · The guard fails closed

- The guard's check moves into hooks of its own:
  - `tool.call` on `Bash` and on `Read`, for Block;
  - `classic.PreToolUse`, for Ask.
- Each Block hook carries `.catch(($, e, next) => next.called ? next(e) : { deny: … })`. The deny text says sabai's guard could not check the call and that the guard can be turned off in `/sabai-settings`.
- The Bash timing stays in its own `tool.call` hook, without a `.catch`: a timing failure must not refuse a command.
- The guard's hooks run whether or not the guard is on, so a failure to read prefs also refuses. This is accepted: reading an atom does not fail in practice, and failing open is the worse error.

## 0c · Description

`plugin.json` `description` is rewritten from what the mod does today:
- the band, the two panes and the guard;
- steps for tool calls, test results, callouts, Thai spinner words and the turn receipt.

It drops "a summary line under tool rows" and "a guard label".

## A1 · Turn receipt

**What it shows.** When a main-conversation turn ends (`agentId` undefined), one line under the answer:

```
✎ 3 files +40 −12 · ✓ 159 passed · › 6 commands, 1 failed
```

Each part shows only when it has a value, and with no parts there is no receipt (a plain answer, or a turn of reads only).

| Part | From | Text |
|---|---|---|
| Files | Successful `Edit`/`Write` calls of the turn | `✎ N file(s) +A −R`. The number of distinct paths. `+/−` sums `asked(old, new)` for Edit and counts a Write's content lines as `+`. |
| Tests | The last Bash call of the turn whose output `testResult` parses | `✓ N passed` or `✗ F of T failed`, the same words as the step's pill. |
| Commands | Bash calls the guard let run | `› N command(s)`, plus `, F failed` when any errored. |

**Turn log.** A new pure reducer in `chat.ts` folds calls into a `TurnLog`:

```ts
type TurnLog = {
  files: Record<string, { added: number; removed: number }>
  commands: number
  failed: number
  test?: { passed: number; failed: number; at: number }   // the turn's last parsed run, with its clock time
  caught?: number                             // clock time of the guard's latest refusal or ask
}
```

- `turn.start` of the main conversation resets the log; subagents' calls are not logged.
- The log is a `$.state` atom (`turnLog`), so the band redraws as moods change.
- `receiptText(log): string | undefined` builds the line. It is pure and in `chat.ts`.
- The `turn.complete` hook returns `completed` unchanged when there is no receipt or Turn receipt is off. Otherwise it returns the receipt the way the spike shows works.

**Setting.** A **Turn receipt** toggle in the Conversation group, on by default (`prefs.chat.receipt`).

## A2 · Guard 2.0

**Rules.** `riskOf(tool, input)` returns `{ rule, reason } | undefined`. `rule` is one of:

| Rule id | Catches | Default |
|---|---|---|
| `wipe` | `rm -rf` aimed at `/` or the home folder (as today) | Block |
| `force` | force-push to `main`/`master` (as today) | Ask |
| `env` | reading a `.env` file with Read or a shell reader (as today) | Block |
| `discard` | `git reset --hard`, `git clean` with `-f`, `git checkout -- .` (or `git checkout .`), `git restore .` (without `--staged` alone) | Ask |

- Heredoc data stays skipped (`withoutData`).
- `discard` reads only the git command's own arguments up to the next shell operator, as `forcedPush` does.
- Paths other than `.` (e.g. `git checkout -- src/a.ts`) pass.

**Actions.** `prefs.guardRules: Record<RuleId, 'block' | 'ask' | 'off'>`, with the defaults above. `prefs.guard` still turns the whole guard on and off; it stays off by default.

| Action | Hook | Answer |
|---|---|---|
| Block | `tool.call` | `{ deny: "sabai's guard refused this: it <reason>. …" }`, plus the toast as today |
| Ask | `classic.PreToolUse` | `{ ask: "sabai's guard: this <reason>" }` |
| Off | — | passes |

**Count.** Each refusal or ask adds one to a `guardCaught` atom (a session count, not stored) and stamps `turnLog.caught`. The band's chip reads `guard` at 0 and `guard · N` after.

**Settings.** The Safety card keeps the Guard toggle. Under it, while Guard is on, there is one row per rule: its name, a one-line note, and three Buttons (Block / Ask / Off) with the chosen one `primary`.

## B1 · Clawd's moods

**Where.**
- While the tasks row shows, Clawd stays in it, as today.
- Otherwise a Clawd of the same size is drawn at the left of the info row, before the folder.
- There is never more than one Clawd in the band.
- With both rows hidden, there is no Clawd.
- The terminal shows the mood as a glyph at the start of the info line.

**Moods,** highest priority first. `moodOf({ log, usage, now, isWorking, lastTurnAt })` is pure, in `model.ts`:

| Mood | When | Sprite mode | Terminal |
|---|---|---|---|
| startled | `log.caught` within the last 3 s | `startle` (new): one jump, a `!` above | `!` |
| sad | the turn's last test run failed (until the next turn starts) | `dizzy` (exists) | `✗` |
| celebrating | the turn's last test run passed, for 4 s after it | `hop` (exists), with confetti | `✓` |
| sweating | context ≥ 90% | `sweat` (new): a drop beside the head | `≈` |
| working | `isWorking` | `run` (exists) | `●` |
| sleeping | not working, and the last turn ended ≥ 5 min ago | `sleep` (new): eyes shut, a `z` rising | `z` |
| idle | otherwise | `idle` (exists) | none |

- Timed moods end on a `$.clock.after` that ticks `now`, the pattern the crew's hop already uses. Sleeping is checked by the existing clock tick.
- New animations:
  - loop in ≤ 1 s, or run once;
  - start from a visible frame;
  - use transforms or opacity only;
  - are honoured by the band's reduced-motion rule.

## Data flow

```
turn.start (main) ──► turnLog = empty
tool.call Edit/Write/Bash (main, after next) ──► turnLog += call
guard Block/Ask ──► guardCaught + 1, turnLog.caught = now
turn.complete (main) ──► receiptText(turnLog) ─► text beneath the answer
AbovePrompt draw ──► moodOf(turnLog, usage, now, isWorking, lastTurnAt) ─► Clawd's sprite mode
```

## Types (contract `types/index.d.ts`)

- `Prefs.chat` gains `receipt: boolean`.
- `Prefs` gains `guardRules: Record<GuardRule, GuardAction>`, with `GuardRule = 'wipe' | 'force' | 'env' | 'discard'` and `GuardAction = 'block' | 'ask' | 'off'`.
- `PluginState['sabai']` gains:
  - `turnLog: TurnLog`;
  - `guardCaught: number`;
  - `lastTurnAt: number` (clock time of the main turn's last end, 0 before any).
- `withDefaults` fills `guardRules` per rule, so saved prefs from 2.0.0 load with the defaults.

## Testing

- **Unit:**
  - the `turnLog` reducer (Edit, Write, Bash ok/failed, a test run, subagent calls ignored);
  - `receiptText` (each part alone, all parts, none, singular and plural);
  - `riskOf` for `discard` (each form, paths that pass, heredoc data, after `&&`);
  - `moodOf` (every priority pair, each timed edge).
- **Hooks:**
  - a Block rule denies;
  - an Ask rule answers `{ ask }` from `classic.PreToolUse`;
  - Off passes;
  - a guard hook that throws before `next` denies (the `.catch`);
  - the count rises;
  - `turn.complete` adds the receipt only when there are parts and Turn receipt is on.
- **UI (terminal and desktop):**
  - Clawd in the info row with no tasks, and in the tasks row with tasks;
  - the `guard · N` chip;
  - the Safety card's rule rows;
  - the band stays under the 100k tree limit with Clawd in the info row and the crew row full.
- Theme contrast: any new text colour passes 4.5:1 (`tests/themes.test.ts`).
