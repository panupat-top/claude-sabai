# sabai 2.4.0 — the info row, redesigned — design

Date: 2026-10-11 · Mod: `sabai` · Status: approved in conversation (preview `race2/info.html` in the session scratchpad, option "B2b · final"), awaiting spec review

## Goal

Today the info row is five boxed chips of equal weight. In its place comes one minimal line that reads in order of importance:
1. the project;
2. the branch and how it stands against its upstream;
3. at the right, quietly, the guard, Node and the git user.

## The row

```
▪ claude-skins  ( ⑂ sabai-2.3 )  ↑2 ↓1 ±3                ◇ guard 7   ⬢ v24   ◆ Panupat
```

**Left, from the left edge:**
- **The project:** the folder mark (13 px, muted ink), then the folder name in the sans face, 14.5 px, bold, the main ink.
- **The branch tag**, 12 px after the name:
  - a pill 20 px tall, fully rounded, filled with the 5H accent (`look.bar('session')`) at 13% opacity;
  - inside, 8 px padding, the branch Octicon (12 px), 5 px, then the branch name (mono 11, weight 600), both in the 5H ink.
- **The sync**, 10 px after the tag: plain coloured counts, mono 10.5, weight 600, 7 px apart.
  - The counts are `↑n` ahead (ok ink), `↓n` behind (context ink) and `±n` changed (warn ink).
  - A count of zero, or one the mod could not read, is not shown.

**Right, ending at the right edge**, left to right:
- **guard**, its shield: `guard`, or `guard N` once it has caught something;
- **Node**, its logo: the major version, e.g. `v24`;
- **the git user**, the git logo: the user's name.

Each item is a 12 px mark, 5 px, then its words (mono 10.5). Items are 16 px apart. Every mark and word on the right is in the muted ink, so the only colour in the row is the branch tag and the sync.

**Vertical:** everything centres on the row's middle line. The row is 22 px tall, 2 px more than the 20 px chips it replaces, so the 20 px tag clears it.

## When room runs short

1. A branch name longer than 24 characters is cut to its first 23 and `…` first, so it cannot push the right side off a roomy row.
2. The right side drops items in this order: the git user, then Node. The guard stays longest, since it is the only place the band shows it: when its words no longer fit it holds on as its shield and count (`◇ 7`), cutting the branch name to make room, and goes only when even that cannot fit.
3. When the right side is empty and the left still does not fit:
   - the branch name is cut with `…` (never below 6 characters);
   - then the folder name is cut with `…`.
4. The sync counts and the tag never overlap the right side.

## Where it applies

- **Desktop, both layouts:**
  - the comfortable band's middle (the hero);
  - the stacked band (compact density, and comfortable under 480 px).
- **Clawd in the stacked band:** where Clawd stands at the left of the info row (no tasks and no live strip), he still leads the row, and the project starts after him as it does today.
- **The terminal:** unchanged.

## What it shows, and what it hides

- **The data is unchanged:** folder, git user, branch with ahead/behind/changes, Node, and the guard chip while the guard is on.
- **Settings still hide each part:** Folder, Git user, Branch and Node in Settings → Info. A hidden or unreadable part is simply absent, and so is its spacing.
- **No repository:** no branch means no tag and no sync.
- **Nothing to show:** the row is absent as today.

## Ink and contrast

The row sits on the surface (no card), so all its words take the surface ink classes, which follow the OS light/dark setting whatever the skin:
- `st` for the name;
- `sm` for the right side and the folder mark;
- `s-session` for the tag;
- `s-ok`, `s-context`, `s-warn` for the sync.

These are the 2.2 surface inks, already checked at 4.5:1. The tag's wash sits under `s-session` text at 13% opacity, and the contrast test is extended to check that text over the wash too.

## Alt text

Unchanged in content and order: `Directory claude-skins, Git user Panupat, Branch sabai-2.3 ↑2 ↓1 ±3, guard 7, Node v24.21.0`. The alt keeps the full Node version and lists only what is shown.

## Code

- **`chips()` keeps its shape** for the terminal and the alt.
- **The desktop row needs the parts apart** (folder, branch, ahead, behind, changes, user, node, guard count). The plan decides how they travel to `svg.ts`: structured fields beside the chips, or an `info` object built from `Env`.
- **A new `infoPart`** in `svg.ts` replaces `chipsPart` in both layouts. `chipsPart` is removed if nothing else uses it.

## Testing

- **Layout:** the row draws the tag, the sync and the right items at their positions at 900 px.
- **Order:** guard, Node, git user from left to right.
- **Narrow:**
  - the user goes first, then Node. At the hero's narrowest middle (760 px with the race, a 336 px middle) a typical project and branch leave room for the guard alone, as its shield and count;
  - at 240 px the branch and folder are cut with `…`;
  - no text overlaps or leaves the band (the same box check the usage styles use).
- **Hiding:** each Settings → Info toggle removes its part. No repository means no tag. Zero counts are hidden.
- **Clawd** still leads the stacked band's info row.
- **Ink:** the row uses only surface ink classes, and the tag text passes 4.5:1 over its wash, light and dark.
- **Limits and XML:** the band stays under its limits, and the SVG sweep stays valid XML.
