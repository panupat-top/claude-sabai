# sabai 2.2.0 — band layout and race — design

Date: 2026-10-11 · Mod: `sabai` · Status: approved in conversation (previews at each step), awaiting spec review

Extends `2026-10-11-sabai-2.2-design.md`. The owner reviewed the desktop and asked for three changes. B2 (In dark mode) is dropped and already removed (commit `b05c210`). This spec covers the other two:
- a new comfortable layout;
- a game-style race box that replaces the live strip and the crew row in that layout.

## Goal

The comfortable band is laid out in three panels:
1. Clawd large on the left, with his mood;
2. the info row and the usage limits in the middle;
3. on the right, while work runs, a little game in which the main conversation and each subagent runs its own lane.

Each lane shows who it is, what it is doing, what it has done, and whether it is failing, succeeding or finished.

**Clawd panel** (left, 108 px wide, a card of the band's full height):
- Clawd at ×3, centred, wearing his accessory, his mood's sprite mode and marks.
- Under him, his mood in words: `idle`, `working`, `caught one!`, `tests failed`, `all green`, `context full`, `sleeping`.
- Under that, the turn's elapsed time while the main turn works.

**Middle** (the rest of the width, less the race box when it shows):
- The info row.
- The tasks row, when Claude keeps a task list, drawn without Clawd.
- The usage limits as rows: label · one bar length for every row · amount or countdown · percent and `→ ~45%`, with the forecast ghost.
- When the middle is shorter than the Clawd panel it is centred vertically.

**Race box** (right, 300 px wide; see below). It shows only while the main turn works or a subagent runs. Otherwise it is gone and the middle takes its width.

**Rows that leave the comfortable layout:**
- the live strip, whose time moves under Clawd and whose step moves into the race;
- the crew row, whose agents move into the race.

Compact and the terminal keep both rows as today.

**Width:**

| Band width | Layout |
|---|---|
| ≥ 760 px | three panels |
| 480–759 px | Clawd panel and middle; the live strip and crew rows come back, as in compact |
| < 480 px | today's stacked layout |

**Settings:**
- With Clawd hidden (`show.clawd` off), the Clawd panel is gone and the race lanes still run (the race is the work, not Clawd).
- With `rows.live` off, there is no race box.
- With `rows.crew` off, the race shows the Main lane only.

## Race box

**Size.** 300 px wide. Its height is a 22 px header plus 28 px per lane plus 6 px padding.
- Lanes: Main, plus up to 3 subagents, newest running first, then the latest finished, kept for the crew's linger minute.
- More agents than fit show a `+N` chip at the header's end.

**Header**, left to right:
- `LV n`: one level per five calls of the turn, all lanes together;
- `● ×n`: test runs that passed this turn, a spinning coin before the count;
- three hearts, one lost per failed Main command this turn (none below zero);
- `×n COMBO`: calls that succeeded in a row across all lanes, reset by a failure, shown from ×2;
- the turn's elapsed time. While only subagents run, it is the time since the first of them started.

**A lane:**
- **Who:** the name at the left, bold. `Main`, or the agent's type (`Explore`, `General` for general-purpose, `Plan`, a plugin agent's name after its colon).
  - Under it, a 9 px note: the step in flight, or the last result (`3/5`, `build failed`, `Done`), cut to fit.
- **Where:** the runner's position along the lane is progress.
  - Main uses its task list (`done/total`).
  - An agent uses `progressOf` (step reports, else its own task list).
  - With no progress known, the runner holds the lane's middle while the ground scrolls under it.
- **What it did:** the ground is a row of small tiles, one per finished call of that member in order, its last 16, coloured by kind:

  | Kind | Colour |
  |---|---|
  | read | context accent |
  | edit (Edit, Write) | 5H accent |
  | command | muted ink |
  | test pass | the band's ok green |
  | failure | alert |

  Other tools are not tiled.
- **What it is doing** (B + D):
  - **B:** the runner holds the tool of its call in flight: a pencil for edit, a book for read, a terminal for a command, a flask for a test command. These are pixel props in `sprites.ts`, drawn in the prop slot.
  - **D:** a soft ellipse under its feet in the kind's colour, pulsing.
  - Between calls it holds nothing and has no glow.
  - An agent keeps its type's hat. Its type tool from the agents pane is replaced here by the in-flight tool.
- **Finish:** a flag at the lane's right end, grey until the member is done, then green.

**States** (the most pressing wins):

| State | When | Drawn as |
|---|---|---|
| out | an agent ended failed | grey body, lying still (`idle` with shut eyes), `OUT` in alert; ground still |
| finished | an agent ended done | at the flag, green flag, `hop`, a ✓ over it, confetti at the flag (first 3 s), ground still |
| tripped | the member's last call failed, for 4 s | `dizzy` with the plaster, `OUCH` in alert above, a spike tile on the ground, name in alert |
| scored | the member's last call was a test run that passed, for 3 s | `hop`, a spinning coin rising over it |
| running | otherwise, while it works | `run`, holding its tool, glow, dust puffs behind its feet, speed lines while a command runs; the ground scrolls left, a far hill line drifts slower behind |
| waiting | Main between calls while the turn works | `idle`, no tool, ground still |

**Animation** (all in the band's stylesheet, each ≤ 1 s or run once, starting from a visible frame, transforms or opacity only, still under `prefers-reduced-motion`):

| Animation | Motion |
|---|---|
| ground scroll | `translateX(-10px)` loop 1 s, with the tiles drawn twice so the loop is seamless |
| far hills | `translateX(-3px)` loop 1 s, opacity .6 |
| dust | two puffs, opacity and drift, 0.5 s, offset by half |
| speed lines | 0.4 s |
| coin | `scaleX` flip, 0.6 s |
| coin rise | 1 s |
| flag | flutter, 0.5 s |
| confetti | 0.8 s |
| glow | opacity, 1 s |
| tool | bob, 0.5 s |

The band redraws each second while work runs (the existing 1 s tick), so timed states end on time.

## Data

New state (`PluginState['sabai']`), written by the existing hooks:

```ts
race: {
  // Per member: 'main' or an agentId.
  calls: Record<string, { kind: 'read' | 'edit' | 'command' | 'test'; ok: boolean }[]>  // last 16 each
  doing: Record<string, 'read' | 'edit' | 'command' | 'test'>                         // call in flight
  fellAt: Record<string, number>     // clock time of the member's last failed call
  scoredAt: Record<string, number>   // clock time of its last passing test run
  combo: number
  coins: number
  mainFails: number
}
```

**Writers:**
- `turn.start` (main) empties `calls.main`, `combo`, `coins` and `mainFails`.
- `agent.spawn` starts the agent's `calls` empty.
- The `tool.call` hooks on Read, Edit, Write and Bash, for every member, by `e.agentId ?? 'main'`:
  - **before `next`:** set `doing`;
  - **after it:** clear `doing` and append the call.
  - A Bash call is `test` when it ran tests (`TEST_COMMAND`), and `ok` when it did not error. A test call is `ok` only when no test failed.
  - Then update `combo`, `coins` and `mainFails`, and stamp `fellAt`/`scoredAt`.
- A guard refusal is not a call (nothing ran).

**A pure function** in `model.ts` builds what the box draws:

```ts
raceOf(
  race,
  agents: AgentRun[],
  tasks: Progress | undefined,
  now: number,
  mainWorking: boolean,
  turnStartedAt: number,
): Race | undefined
```

- `Race` has `lv`, `coins`, `hearts`, `combo`, `elapsedMs`, `more` and `lanes`.
- Each lane is `{ who, type, note, progress?, calls, doing?, state }`.
- It returns `undefined` when neither the main turn nor any agent is at work.

## Drawing

In `svg.ts`, behind `bandSvg`:
- `heroBand(...)` draws the three panels.
- `racePart(look, race, W)` draws the box.
- New pixel props in `sprites.ts`: `TOOLS: Record<'read' | 'edit' | 'command' | 'test', Prop>`.
- `sprite()` accepts a held-tool override.

`BandOpts` gains:
- `race?: Race`;
- `layout` is decided inside `bandSvg` from density and width, as above.

The prototype `hero` option and `heroBand` written for the preview become the real code, under tests.

## Terminal

Unchanged: the info line, the live line, the tasks line, the crew line and the usage line. The race is a desktop drawing.

## Testing

- **Unit:**
  - `raceOf`: lanes order and the 3-agent cap with `+N`; Main's progress from tasks or none; each state and its timing edge (4 s tripped, 3 s scored); out and finished; hearts floor; combo reset; LV steps; `undefined` when idle;
  - prop drawing for each tool.
- **SVG:**
  - three panels at 900 px (the race box present while working, gone when idle);
  - two panels at 600 px with the live strip and crew rows back;
  - the stacked layout at 400 px;
  - a lane's states draw their marks (`OUCH`, a coin, ✓ and a green flag, `OUT`);
  - the stylesheet has each animation and the reduced-motion rule.
- **Hooks:**
  - a subagent's Read, Edit and Bash calls land in its own lane, and Main's in Main's;
  - `doing` is set while a call runs and cleared after;
  - a failed command trips its member and costs Main a heart only for Main;
  - a passing test run adds a coin.
- **Limits:**
  - the band with every row, three running agents and a fourth over the cap, a forecast, a hat and the race stays under the 100k tree limit;
  - its SVG is ≤ 131,072 characters.
- **Contrast:** any new text colour passes 4.5:1 (`tests/themes.test.ts`).
