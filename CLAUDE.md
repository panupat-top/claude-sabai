# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Claude Code plugin marketplace (`claude-sabai`, `.claude-plugin/marketplace.json`) holding **mods**: plugins built on Claude Code's function-hooks API (Claude Code ≥ 2.1.287). Each mod lives in its own folder under `plugins/`. Today there is one, `plugins/sabai`. The plan, decisions and backlog are in `docs/PLAN.md` (written in Thai).

## Commands

Run from the repo root; each mod is checked on its own folder.

```bash
claude plugin validate .claude-plugin/marketplace.json   # marketplace manifest
claude plugin validate plugins/sabai                # manifest + what the hooks module hooks/calls, and anything the engine would refuse
claude plugin test plugins/sabai                    # runs every *.test.ts(x) under the folder (no per-test filter)
tsc -p plugins/sabai                                 # type-check; needs the engine-laid types (see below)
claude --plugin-dir plugins/sabai                    # run the mod in a session; saving a file hot-reloads it
bash statusline/hub.test.sh                          # the terminal status line's tests (HUB_BASH=/bin/bash for macOS's bash 3.2)
git config core.hooksPath .githooks                       # once per clone: pre-commit validates, type-checks and tests
```

- `plugins/sabai/tsconfig.json` extends `.claude-plugin/types/tsconfig.json`, which Claude Code writes beside a mod only after it has loaded it (hot reload or `--plugin-dir`). That folder is gitignored and absent on a fresh clone, so `tsc` works only after one load. CI (`.github/workflows/check.yml`) therefore only validates and tests; the pre-commit hook type-checks when the types exist.
- The API reference is that laid file, `.claude-plugin/types/claude-code/index.d.ts` (~14k lines, every event, `$` noun and element prop). Grep it rather than guessing an API.

## Dev and production installs on the owner's machine

An installed plugin runs from a copy in `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/`, re-copied only when the version changes: `/reload-plugins` reloads that copy, not the repo. So the machine keeps two channels apart:

- **Production**: the `claude-sabai` marketplace comes from GitHub (`claude plugin marketplace add panupat-top/claude-sabai`), as users install it. After a release is merged and pushed, `claude plugin marketplace update claude-sabai` then `claude plugin update sabai@claude-sabai`.
- **Dev**: `~/.claude/settings.json` sets `"env": { "CLAUDE_CODE_PLUGIN_DIRS": "<repo>/plugins/sabai" }`. Every session, the desktop Code tab included, then loads the checked-out branch in place as `sabai@inline`, which silently wins over the installed copy; a save reloads it. The env is read when a session starts, so a change to it needs a new session.
- `claude plugin list` shows which is loaded (`sabai@inline` with a path is dev). To see a release as users get it, remove the env line, open a new session, then put it back.
- To preview a drawing outside the engine, show each SVG as its own `<img>` (a data URI): inline SVGs in one HTML page share their `<style>` rules, so class colours leak between themes.

## sabai architecture

A band above the prompt (comfortable: three panels — Clawd large with his mood, a reason and his tricks, the live strip and task list over the usage limits in one of four styles filling the band's height, and a race box where Main and each subagent run a lane while work runs; compact and narrow: stacked rows with the live strip and crew; a top row above it holds the info row at the left and the toolbar as Lucide icons at the right), two panes (agents, in three boxes: Now, the crew at work as a timeline and a lane for Main and each agent; Viewing, the run viewed; Earlier, the crews before; settings: the look (layout, theme, bar style), then the band's parts as they stand in it, top to bottom (the info row's parts, Clawd's extras, Band: the parts with no choices of their own, the usage's style and limits, Subagents: the race and the pane's options), then what lies outside the band (chat, the guard, notifications), reset, then the about line (`aboutLine` of `env.build` from `readBuild`: the manifest's version, `Release (<marketplace>)` when `$.plugin.root` sits in the plugin cache (`marketplaceOf`) else `Dev` with the mod repo's branch@sha, and the engine's version); a part with choices has its On/Off in its group's head; the layout, theme and usage style are drawn choices, each a sketch of the one in use over a row of Buttons named for the choices (`densityPreview`; `themePreview`, the pair in use in fixed colours so both halves read in either mode, over a row of light themes and a row of dark ones; `usageSketch`, three cards side by side when there is room), and the bars, info row and chat show samples), and touches to the conversation (tool calls drawn as one-line rows, test results, callouts, a receipt under each working turn). Clawd shows the session's mood in the band. The mod is the desktop Code tab's alone: a terminal or `-p` session is left as Claude Code draws it, with no reads, commands, tool, prompt section, guard or notifications.

- **Desktop only.** `session.start` sets the mod up (`setUp`: saved choices, commands, the step tool, the clocks, the git and node reads) when `$.session.surfaces()` holds `desktop`, else `session.attach` does when the desktop attaches (an SDK session such as the Code tab's starts drawing nowhere, and the desktop attaches on its first ask to draw), and failing both the band's first desktop draw does (from `$.clock.after`); `setUp` sets the module's `desktop` flag, and every engine-event hook passes straight through (`return next(e)`) while it is off. Render hooks pass through on any `e.surface` but `desktop`, so a terminal attached to the same session sees the engine's own rows.
- `hooks/register.tsx` is the only module that touches `$`. It hooks engine events (`session.start`, `session.attach`, `session.measure`, `tool.call` on `TaskCreate`/`TaskUpdate`/`TodoWrite`/`Edit`/`Write`/`Bash`/`Read`/`Monitor`/`TaskStop` and, with no matcher, every subagent call and the step tool, `tool.check`, `agent.spawn`, `turn.step`, `turn.complete`, `turn.start`, `prompt.compose`, `prompt.submit`, `session.compact`, `session.end`), writes state, registers `/sabai-settings` and `/sabai-agents`, and renders `AbovePrompt` (the band), `Pane` (agents, settings) and the conversation rows `ToolUse`, `ToolGroup` and `AssistantMessage`.
- **The turn log and the guard.** `turn.start` empties a `turnLog` atom; `tool.call` hooks on Edit/Write/Bash fold the main turn's calls into it (`logged`), and `turn.complete` files the log under the turn's answer in `receipts`; the `AssistantMessage` row whose text is that answer draws the receipt line (`receiptSvg`) under itself. A turn with no answer of its own returns `receiptText` as its text, a notice under it. The guard blocks in `tool.call` and asks in `tool.check` (`{ decision: 'ask', reason }`), per rule as `prefs.guardRules` says; its `tool.call` and `tool.check` hooks carry a `.catch` that refuses (`failClosed`), since a failed hook is skipped and its call would run. Each catch counts in `guardCaught` and stamps the log, so Clawd startles.
- **The agents pane.** Each `AgentRun` carries what its detail shows: `agent.spawn` sets its `crew` (the main turn's `turn:<start>`, its workflow's `wf:<runId>`, or its parent's), `brief` and `background`; `turn.step` adds every request's new tokens (input, cache writes, output; not its cache reads) to `spent`; the `tool.call` hook with no matcher logs each subagent call through `logAgentCall` (in flight in `doing`, then `calls` with its time and outcome, `tools` counted, `files` read or changed with lines from `logged`), and runs a tool the race's own hooks leave out in the agent's lane, so the band and the pane count alike; the step tool keeps its `notes`. A finished agent sent more work runs again in the crew at work, its report kept in `rounds`. `crewsOf`/`openCrews` give the crews at work (shown in full) and the earlier ones (a line each in a foldable box, by day when they span more than one); `spawned` keeps the newest `CREWS_KEPT` crews. `agentMood` and `laneLine` say how each agent stands (one line per state, in the band's words, never picked at random). A run's head (`agentHeadSvg`) says beside its mood tag what it runs on (`runsOn`: its model after a robot, its effort after a gauge, in its family's hue, `FAMILY_HUE`), never its calls, which the Calls box lists. The main loop's turns are runs too, in their own `mains` atom so the band, race and toolbar (which read `agents`) never see them: `turn.start` opens one (`main:<start>`, closing the one before), `turn.step` and the same `tool.call` hook (`logAgentCall` with `main`, no race of its own) fill it, `turn.complete` ends it with Claude's answer as its report; the pane sets each before its crew's first agent, drops a finished one that called nothing and started no agent, and keeps older ones only where their crew had agents. A Main turn that ended while its crew's agents run is drawn waiting on them (`waitingOn`, mood `waiting`, never stored), as the race's `Waiting on N` says, and the Now box, like the race's header, counts the subagents alone (`N running · N done`). Viewing shows the run viewed (View on its lane toggles it, Close shuts it; none at first), else an invitation and `needsLook`'s agent; its parts are unboxed titles over their drawings. When an agent finishes with a report and Thai summary is on, `summarize` asks Haiku (`$.model.complete`) for Thai bullets, `summary: 'pending'` meanwhile (a reload asks again; at most two ask at once, `inTurn`); no answer leaves none. The pane spends `PANE_BUDGET` on its drawings, each costing its escaped source and its alt, in order (overview, detail, earlier lines, lanes), and counts the lanes that do not fit. Clear keeps the crews the pane shows in full, Main's and the agents' alike.
- **State** lives in `$.state` atoms declared in the contract `types/index.d.ts` (`interface PluginState['sabai']`); a draw `read`s them and redraws when an `update` writes. `now` is written every 30 s, and every second while the main turn or an agent works (the live clocks, `tickWhileWorking`: started by work, it stops itself once nothing works, so an idle session reads nothing each second), so the band is redrawn once a second during work. Module variables (e.g. `cwd`, `desktop`) are only for things `session.start` re-sets, since a reload starts the module over. The chosen theme pair is also persisted with `$.store` (`theme`; `themeOf` keeps each side only when it names a theme of its mode, so an older version's `skin` starts Mono and Ink).
- **The band's layout.** `bandSvg(p, list, W, opts: BandOpts)` draws the stacked band (compact draws its usage with `usagePart` at `USAGE_MIN_H`; the comfortable band below 480 px keeps two-line cards, `cardsPart`), or with `opts.hero` (comfortable density, W ≥ 480) `heroBand`: the Clawd panel (his headline from `MOOD_WORDS`, the `moodLine` reason, his `trickOf` trick), the middle (the live strip and tasks; then `usagePart` in `prefs.usageStyle`: tiles, rings, columns or rows) and, from 760 px, `racePart`; below 760 the live strip and crew rows stay in the middle. The band carries no info row: the top row above it holds `infoSvg` (`infoPart`: the project, a branch tag with sync counts, then git user and Node in the muted ink, every chip packed from the left on a card of the band's colour that fills the room the icons leave, `W` less `TOOL_CHIP` per icon; Node at its full version; Clawd leads it in the stacked band when no tasks row or live strip holds him) and, at its right, the guard as a green `shield-check` (`toolIconSvg('guard', …, 'ok')`, pressed it opens the settings) then the toolbar as `toolIconSvg` icons (compact while the surface offers it, agents, settings; a count and the warn, alert or clay ink drawn in, the colour on one at a time). Each icon is a tile of the card as tall as the info row, its Lucide shape a mask over a rect in a fill class (`m`, `c-warn`, …), so the theme's stylesheet colours it; the row has no column gap, so it reads as one strip. The band's height is the tallest of Clawd's panel (112 px), the race and the rows above the usage plus 50 px; the usage fills what is left. The engine's context reading is the last response's, so `readUsage` takes its local estimate (`$.session.usage({ breakdown: 'summary' })`, no request; `contextEstimated`, drawn with a `~`) before a first response and after a main-loop compaction (`session.compact`) or a `/clear` (`session.end` with reason `clear`, which also empties the turn, race, tasks, receipts and the guard's count), until `session.measure` brings the next reading. Until the session has read, the band is a still skeleton of the same height: `usage` is `null` until the engine answers (then `meters` gives `pending` meters drawn as an empty track and a dash), and the info row draws two bars until the branch is read (`env.read`; the folder shows at once, and git user and Node each when it answers); an answer with nothing to show leaves `usageNote` in the usage's place. The race's state is the `race` atom (`RaceLog`: each member's tiles, call `count`, call in flight, latest call's words `said` (`actOf`'s `now`, written by `stepping` for every call, Main's MCP calls included), its call's kind as the pane names it `acting` (an MCP call's plug, a skill's bulb, which `doing`'s four race kinds lack; the live strip's step takes it too), the skills and MCP servers it has called `used` (`usedBy`: `skill:pdf`, `mcp:Browser`, once each, added in `stepping`'s own write) and when its latest call ended `lastAt`, `failed` calls, last fall and score, and the turn's `total` and `fails`), written by the Read/Edit/Write/Bash hooks through `racing` and laid out by `raceOf`, which shows nothing without agents (the live strip tells Main alone), names lanes by the agent's description, says each by its plan's step, else its call in flight, else `Thinking 12s` since its last call (the pane's `laneLine` adds the files it touched last, `focusOf`: `· editing svg.ts, chat.ts`, by the newest, `touched` keeping a run's files newest last), merges agents of one type when more run than three lanes hold (summing their counts; shared lanes first, so a merged type is never the one left out), gives each agent its `agentMood`, `quietMs` while quiet and `fresh` for `FINISH_MS` after it finished, and tells Main `thinking` (working, no call in flight) from `waiting` (not working). Every lane's words (the race's rows, the pane's lanes, the head's mood tag, the live strip) lead with `statusTile`, a frameless duotone (the Lucide shape filled with its theme hue's soft tint inside its deep outline, from the `sabai-du-*` defs, which leave the fill to each placement; 14 px in the race, a head's tag, a timeline's bar ends, the crew row's and the Earlier row's counts, 16 in a lane and the live strip). A race row counts its lane's skills and MCP servers (`Lane.uses`) as a lightbulb and a plug before its failed calls; a pane lane that called any grows a 17 px row of chips (`usesChips` from `usesOf`: an MCP tool under its server, the one in flight first and pulsing, then the most called, `+N` past the room), each on its hue's `kb` ground in its `kf` ink: its call's icon pulsing while one runs, else its state's (thinking's hopping dots, waiting's turning hourglass, quiet's fading moon, context's rocking gauge, done's check, failed's cross, stopped's circle-stop, still), moving by `TILE_MOTION` (in `MOTION` and the pane's `MOVES`), each animation on a wrapping group since a CSS transform would replace the icon's own placement. `racePart` draws a 22 px row per lane: a mood stripe, the Clawd (Main in the captain's cap) at `RACE_SCALE` as paths, name and step, then `✗` failures, a plan's done/total and bar, and the time; a fresh finish flashes its row with confetti, then settles, a fresh failure (`out`) falls on a red-flashing row, then settles, and a stopped agent settles at once: a settled member keeps its Clawd dimmed, and its line's `statusTile` (a check, a cross, a stop) is the one mark of how it ended, the crew row's counts (`statusMark`) and the timeline's bar ends drawing the same tiles. In the pane, an ended lane wears no badge on its Clawd (its line's tile says how it ended, so nothing overlaps); `endTint` flashes the lane for `HOP_MS` after it ends, while its Clawd hops or falls. Main is named so in the race and the pane, in the captain's cap. The main turn's start and call in flight are `turnStartedAt`/`liveCall` (its atom key is still `liveStep`). `background` holds the ids of the background tasks the main conversation started: a Bash call's `backgroundTaskId` (asked for, Ctrl+B or a timeout) and a Monitor's `taskId` add one, `TaskStop`'s `task_id` and a `prompt.submit` from a `task-notification` (`endedTasks`: each block with a status other than running) take it away; while it is the person's turn, `N background` after a pulsing dot takes Clawd's line in the comfortable band. The live strip (`livePart`) shows the step in flight as its kind's tile (`kindTile`, blinking) with its words and its own time (`liveCall.at`), or three hopping dots and `Thinking 12s` (`thinkingMs`, timed as the race times Main); at the right the main turn's tiles from the race log (`calls.main`, the last `RACE_TILES`, with `+N` for the earlier `count`), the lines its edits changed (`turnLog.files`) and its tests; below 260 px of room the step keeps it and the lines and tests go. `prefs.extras` turns Clawd's accessories and tricks off. The race's CSS rides inside its own box so other drawings stay small.
- **Pure logic** — `model.ts` (meters with levels, chips, task reducers, formatting, `moodOf`, `moodLine`, `trickOf`, `resetClock`, `accessoryOf`, `raced`, `paceOf`), `agents.ts` (subagent run reducers and their call log, `progressOf`, `raceOf`, type styles, crews, `agentMood`, `laneLine`, the summary's prompt and reading), `chat.ts` (tool summary lines, `actOf` for a subagent's call, test-output parsers, callout splitting, the turn log's `logged` and `receiptText`), `themes.ts` (the two looks' keys and names, `contrast`), `guard.ts` (`riskOf`, `GUARD_RULES`, the commands the guard catches) — takes plain values and is unit-tested directly.
- **Drawing** — `svg.ts` builds the desktop SVGs (`bandSvg`; the agents pane's `crewSvg`, `laneSvg`, `agentHeadSvg`, `toolsSvg`, `stepsSvg`, `activitySvg`, `filesSvg`, `earlierSvg`) from a `Look` (`lookOf(theme)`, cached per pair: stylesheet, bar colours, pill, Clawd tint, and the theme's variables). A theme (`themes.ts`) is a set of colours for one mode: card, track, pill, nine text inks, six bar colours and nine tile hues; there are three for light (`LIGHT_THEMES`: Mono, the default, Pastel, Matcha) and three for dark (`DARK_THEMES`: Ink, the default, Forest, Synthwave), and the person picks one of each (`Theme`, `{ light, dark }`). The stylesheet sets the light theme's inks and, under `prefers-color-scheme: dark`, the dark one's; bars, the pill and the tiles are variables (`var(--bar-tasks)`, `var(--pill)`, `var(--kb-ok)`) each drawing declares for the ones it uses, light and dark (`themeVars`). The theme's colours are fixed values, checked by the theme tests; Clawd keeps his clay in every theme, and words drawn on the bare surface keep the OS's ink (`TEXT`, `SURFACE_INK`). No theme paints a background, so the band sits on the surface. Small drawings redrawn often (toolbar icons, the info card) carry only their classes' rules (`leanCss`), and a call is a tile (`kindTile`) of its kind's Lucide icon (`CALL_ICON`), placed with `<use>` from defs the drawing carries once (`iconDefs`). Statuses and call kinds take the theme's hues (per hue a tile ground `kb`, its glyph `kf` and lines and bars `kl`), painted as `var(--kb-ok)` and so on; a glyph reads at 5:1 on its ground (the theme test); `sprites.ts` holds pixel sprites and their CSS animations; `icons.ts` holds the info-row marks (Octicons / Simple Icons path data), and `strokes.ts` the chat's Lucide stroke icons (animated by CSS in `svg.ts`), generated once from Lucide's files.

| **workflow run** | one run of a dynamic workflow; its subagents are shown together under it, its box and Earlier row named so | |
| **teammate** | an agent team's teammate (`agent.spawn`'s `isTeammate`): the docs keep it apart from subagents, so its head says so | |
| **round** | a finished subagent sent more work runs again: round 2 | |
| **task**, **task list** | Claude's task list (TaskCreate, TaskUpdate, TodoWrite) and its items | a subagent's job: its **description** (its name) and **prompt** ("Asked to") |
| **step** | a step of a plan: the step tool's steps, the STEPS meter | a model request, which is a **request** |
| **Progress** | a run's plan: its step tool's steps, else its task list | "Plan", the subagent type |
| **background task** | a Bash command or Monitor run in the background ("N background" under Clawd); a **background subagent** is a subagent run so | |
| **running · done · failed · stopped** | a run's state; done is the docs' "completed", failed an error or refusal, stopped the person's choice | |
| **pane** | a desktop side view: Subagents, Settings | "panel" |

| **skill**, **MCP server** | a skill the Skill tool loaded, by its name; an MCP tool's server, by its own name without ids (`mcpName`): the chips and the race's counts name servers, Tools and Calls name each tool | an MCP tool's raw id |

A run's model requests are `AgentRun.requests`, a lane's words `Lane.line`, the call in flight `liveCall`.

## Engine constraints that shape the code

- A render tree (a band or a pane) must stay under 100,000 characters serialized, or nothing of it is drawn ("Nothing to show yet" in a pane). A Clawd sprite alone is ~14k.

- `$` cannot be passed across an import: any helper taking `$` must be declared in `register.tsx` itself.
- `read`/`update` must name their atom where they are called (an atom const of the file, or `memberOf` of one): an atom passed in a variable makes the module fail to load, since the engine lists a module's state by reading the calls. Choose between atoms with a branch (`updateRuns`).
- Branch a render hook on `e.surface !== 'desktop'` (then `next(e)`): it also narrows `$.ui.resolve(e)` to the desktop's table, which has `Svg`. The terminal's table lists `Svg` too but cannot draw it.
- The desktop draws an `Svg` as an image. In a column its siblings take new lines; in a `Box flexDirection="row"` it sits beside `Button`s and `Markdown`s (checked on the desktop), which is how the top row puts the info row's own SVG (`infoSvg`, packed from the left and as wide as it draws) beside the toolbar's icons. With no `width` prop the surface fits the markup to the slot: a wider one is scaled down, hence drawing at `bodyColumns × 8.25`, and in a pane a narrower one is stretched up to the pane's width (the settings' 320 px bar sample was), so a drawing meant to keep its size passes `width` and `height`. Svg width/height must be 1–4096 px and its source ≤ 131,072 characters; clip-path ids must be unique (`sabai-*`).
- The desktop draws a `Button` as a native button from its `label` alone (children, colours and `hover` are ignored; a `hotkey` shows as a keycap), and a `Button` holding an `Svg` is refused (the whole hook is skipped). Put what the desktop should show in `label`. A clickable icon is a `Markdown` whose text is an image link, `[![alt](data:image/svg+xml;base64,…)](https://sabai.invalid/<kind>)`, answered by `onLinkPress` (no browser opens; checked on the desktop): one Markdown per icon in a row Box sits side by side, while several in one Markdown stack, and a `file:` image is not drawn. A large image link (a 220 px sketch) took presses unreliably on the desktop, so the settings' sketches sit over Buttons rather than being links; in the agents pane an image link took no presses at all, even at the toolbar's size (a lane's eye, 30×24), so lanes keep their View Button. Of the common commands the Code tab offers `/clear` and `/compact`, not `/rewind` or `/resume`.
- A pane `Svg` keyed the same while it comes to show another subject (the agents detail switching agents) kept its old image on the desktop: key such drawings by their subject (`detail-calls-${id}`).
- SVG animations: the desktop draws each drawing as an image and redraws the agents pane every second while an agent runs, restarting its animations. Keep loops ≤ 1s, and start every animation from a visible frame (an image can sit on its first frame); a `stroke-dashoffset` draw-in never runs there, so use transforms or opacity.
- Native `Text`, `Button` and `Markdown` keep the surface's own ink, which follows the OS light/dark theme; `Button` and `Markdown` take no colour. Never put them on a fixed theme colour (a `Box` `backgroundColor`): the ink may not read on it.
- The desktop raises no `classic.*` event to a hooks module (checked with a `*` logger: the engine's own events arrive, no `classic.Stop`, `classic.PreToolUse` or `classic.SessionStart`), so what a classic hook's input alone carries (`Stop`'s `background_tasks`) is out of reach there; take it from the engine's events and tool results.
- `session.measure` only fires on the next API response, so `session.start` reads `$.session.usage()` itself.
- Work started from a button press is cancelled when the press ends; run it via `$.clock.after`.
- In the desktop Code tab `$.ui.status` is not shown and `/config` is unavailable, so settings are slash commands.
- A drawn tree's size depends on the drawings in it: the agents pane draws its parts by their drawn size (`PANE_BUDGET`; its drawings carry only the inks, motion and faces they use, and its Clawds as paths), and repeated marks (dither dots, ticks) are capped so a very wide band stays inside the limits.
- Conversation rows: a `ui.render` hook on `ToolUse`, `AssistantMessage`, `UserMessage` or `ToolGroup` replaces the row, and a tree wrapping `await next(e)` keeps the engine's row with ours under it (both checked on the desktop). Round borders and `Text` colours are honoured there; an `Svg` is drawn as an image and, without `width`/`height` props, stretched to the row's full width, so chat drawings are fixed-size and pass both. The desktop always draws its own `ToolGroup` line and the thinking summary, and shows no `SessionMode` footer, so the guard label lives in the band's info row. Transcript `Text`/`Box` colours are theme keys (`success`, `error`, …), since the conversation follows the person's own theme, not sabai's. A standalone tool row's `output` is often absent on the desktop (its result is a separate `ToolResult`), so steps fall back to the call's input. Bash durations are a `StateFamily` keyed by `tool_use_id` (read with `memberOf(atom, e)`), so a new call redraws only its own row; a call that opened the permission dialog (`classic.PermissionRequest`) shows no time, while the auto-mode classifier's `ask` keeps it.
- Turn ends and permissions (checked on the desktop): `turn.complete` returning `{ text }` keeps the answer and draws the text as plain text in a folded "Claude Code notice" under it, prefixed with the names of the plugins hooking it. An event registered twice without a matcher is refused at load, so a feature extends the existing hook. `classic.PreToolUse` answering `{ ask }` opens no dialog; `tool.check` answering `{ decision: 'ask', reason }` opens the permission dialog with the reason in default mode, while in auto mode the ask goes to the classifier, which may allow it. Neither hook sees the permission mode. An SVG drawing follows the OS's light/dark switch live, both through a class set inside `@media (prefers-color-scheme: dark)` and through a CSS custom property used as a `fill="var(--x)"` attribute (checked on the desktop). A `ToolGroup` row starts folded; `isExpanded: true` unfolds it into its steps. An `AssistantMessage` carries no turn id, but the final reply's `text` equals `turn.complete`'s `answer`, which is how the receipt finds its reply.
- Everything the band shows must come from the engine or the project's own `git`/`node`; values that cannot be read are hidden, never faked. No credentials or external files.

## The terminal status line (`statusline/`)

`hub.sh` is a Claude Code `statusLine` command for terminal sessions, which sabai leaves alone: two lines (folder, branch and sync, model, effort, cost, time; then context, 5H and 7D line bars with their resets), each part led by a Nerd Font v3 icon from its Material Design range (U+F0000 up, the same code points as the `@mdi/font` webfont, so a browser preview can draw them), written as literal glyphs since bash 3.2 has no `\U` escapes; `SABAI_HUB_ICONS=0` drops them. It is not part of the mod and has its own version in its header. It runs on every status refresh, so it keeps to one `jq` (all fields joined by `\x1f`, since tabs collapse empty fields), one `git status --porcelain=v2 --branch`, and helpers that write with `printf -v` instead of forking `$(…)`; about 35 ms against the old script's 300. It must run on macOS's bash 3.2 (no `${x^^}`, no associative arrays; a substring counts bytes, so join with `${s:+ · }` rather than cutting a multibyte separator off). Colours are the terminal's 16 ANSI ones so it follows the person's theme. `HUB_NOW` pins the clock for the tests.

## Conventions

- `README.md` is for people installing and using the mods, kept short (what it is with screenshots, install, commands, privacy, the common troubles); `docs/guide.md` holds every part and setting in detail, and the README links to it. The screenshots in `docs/images/` come in a light and a dark file each (`<picture>` picks one) and are drawn by the mod's own drawing code, so redraw them when a drawing changes. Development notes belong here; the roadmap and decisions in `docs/PLAN.md`.
- Code, comments, commit messages and repo docs are in English; `docs/PLAN.md` is in Thai.
- A release bumps the mod's `version` in both `plugins/<mod>/.claude-plugin/plugin.json` and its entry in `.claude-plugin/marketplace.json`, and updates the README and the guide if commands or behaviour changed. Once it is pushed to `main`, it gets an annotated tag `<mod>-vX.Y.Z` and a GitHub release (`gh release create`) with notes for users, so the Releases page stays current.
- Before committing, run validate, test and `tsc` (the pre-commit hook does all three). Commit messages: an imperative subject line, then a short bullet list of what changed.
- User-visible text is English, in the glossary's words, the same in the band and the pane, one wording per state and never picked at random. The one exception, by the owner's choice, is Haiku's Thai summary bullets (Settings › Subagents › Thai summary); the mod no longer replaces the desktop's spinner word. Keep every text colour at ≥ 4.5:1 on its card, in light and dark; the theme test enforces it for every theme.

## Tests

Tests import `test`, `expect`, `mock` from `claude-code/testing`. In a test, `$` is the engine's (it has no `env`, `settings`, `store` or `fs` nouns of its own; a test answers `fs.read` with `on('fs.read', …)` as it does `store.get`), and hooks registered with the test's `on` sit beneath the plugin and stand in for the engine — e.g. `process.run`, `session.usage`, `store.get` answered as `{ value }`, while object-result events like `session.start` return the object directly. UI is checked by `$.ui.mount({ plugin, surface, component, requestId, props })` and `findAll` on the `desktop` surface; the test engine answers `session.surfaces` (`['desktop']` unless a test says otherwise), and one test checks that a terminal session is left alone. Contrast of every theme's text colours (≥ 4.5:1 on its card), white on its pill, its tile glyphs (≥ 5:1) and its bar track is asserted in `tests/themes.test.ts`.
